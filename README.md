# 国土调查地类拆分核算 API

国土调查更换地类图例后，统计员需要估计：旧图中某旧地类的像元，有多少能算入指定的新地类，
以便决定哪些图幅还需外业复核。本服务登记旧图幅各地类像元数、外业补报的新地类整幅总数、
新旧地类对照表（一个旧码可对应多个新码），并对任意「图幅 + 一对新旧地类」给出
**重合像元数的最小值与最大值**；两值相同即为确数。

## 数学模型

每个图幅独立构成一个运输型拆分问题：

- 变量 `x[旧码][新码] ≥ 0`（整数），仅当对照表允许该对时存在；
- 行约束：每个旧地类的像元必须全部分配出去（= 旧图登记数）；
- 列约束：每个已复核新地类的列和必须恰好等于补报的整幅总数；
- 未复核新地类列和不限，吸收剩余像元。

在此多面体上对查询变量求最小/最大。约束矩阵全幺模，故用**最小费用最大流**
（`app/solver.py`，纯 Python 实现，无外部求解器依赖）直接得到整数最优解：
给查询边费用 ±1 分别求最小、最大；已复核新地类的汇边挂大 M 负费用，
保证「满足全部复核总数」在字典序上优先成立，同时也用于可行性判定。

## 一致性设计

- 普通计数更新（登记计数、更正/撤销复核数）在 `BEGIN IMMEDIATE` 事务内
  **先写入、再按当前生效图例校验受影响图幅的可行性**：只要有图幅无解，
  整次更新回滚，返回 409 并列出受影响图幅及原因；因此已提交状态恒可行。
- 整表换对照表（`PUT /legend`）分三个阶段，**全库核对期间不再持有任何
  数据库锁，补报/更正/撤销照常按生效图例提交**：
  1. **快照**：取提交前已入库的各图幅计数与当前图例版号；
  2. **全库核对**：用新图例在内存中逐图幅判定可行性（纯计算，不阻塞写入）；
  3. **发布**：短暂取写锁，重新读取计数，只对核对期间**新增、改动或撤空**
     的图幅按最新计数重新判定，其余图幅沿用第 2 步核对结果；仍有图幅无解时
     返回 409 并列出**全部**冲突图幅，原图例与版号继续供数；
- 换表被拒或写库失败时图例事务整体回滚，**已入库的图幅计数更新独立提交、
  仍然有效**；
- 查询（`/overlap` 等）只读已提交状态：单连接 + 全局读写锁，单次查询中
  图例、版号、计数取自同一个已提交快照。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/legend` | 查看当前对照表（含版本号） |
| PUT | `/legend` | 整表更换对照表，体为 `{"mapping": {旧码: [新码...]}}` |
| PUT | `/sheets/{id}/old-counts` | 登记/替换图幅旧地类像元数，体为 `{"counts": {旧码: 像元数}}` |
| PUT | `/sheets/{id}/review-totals` | 补报/更正图幅新地类复核总数，体为 `{"totals": {新码: 总数}}` |
| GET | `/sheets` | 列出已有数据的图幅及像元合计 |
| GET | `/sheets/{id}` | 查看某图幅已登记计数 |
| GET | `/overlap?sheet_id=&old_code=&new_code=` | 查询重合像元数 min/max，`exact=true` 时 `value` 为确数 |

计数均为非负整数（负数返回 422）；0 等价于不登记；替换式语义便于更正。
不在对照表中的新旧地类对，重合像元数恒为 0（`in_legend=false`）。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
```

服务监听 `http://localhost:8000`，Swagger UI 在 `http://localhost:8000/docs`，
SQLite 数据落在名为 `land-data` 的卷中（容器内 `/data/land.db`）。

### 本地运行

```bash
pip install -r requirements.txt
uvicorn app.main:app --port 8000          # 数据库默认 ./data/land.db，可用 LAND_DB_PATH 覆盖
```

### 测试与演示

```bash
python3 -m pytest tests/ -q               # 31 个单元/端到端/换表并发测试
bash scripts/demo.sh                      # 对 localhost:8000 走一遍完整流程（含换表前后对比）
```

`scripts/demo.sh` 演示：登记对照表与两幅旧图 → 换表前查询（区间）→ 补报复核数 →
查询变确数 → 更正复核数 → 换表核对期间继续登记复核数 → 整表换表 → 换表后查询变化 →
非法换表被 409 拒绝并列出受影响图幅 → 非法复核数被拒且原数据不变。
换表三阶段（快照/核对/发布）的并发场景由 `tests/test_swap.py` 覆盖，包括：
核对期间补报新增冲突导致 409 退回、撤销冲突计数后换表成功、未变更图幅沿用
核对结果、整幅撤空、写库失败回滚且原图例继续供数。
